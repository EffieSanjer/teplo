# Модель безопасности и ограничения первой версии

## Защищается приложением

- Взаимная дружба даёт доступ к профилю, вишлисту (включая архив) и связанным
  фотографиям, но не к каталогу друзей, членству группы или групповым сюрпризам. Авторские
  операции над чужими желаниями запрещены. Доступ проверяется на каждый запрос;
  удаление дружбы закрывает его в обе стороны, кроме независимого доступа через
  общую группу. Уже просмотренные данные отозвать нельзя.
- Сюрпризы друзей хранятся отдельно от Telegram-групп и личных пространств входа
  (`friend_surprise_spaces`, один список на получателя). Читать записи, архив
  и связанные фото могут только прямые подтверждённые друзья получателя,
  включая добавленных позже. Дружба с автором не даёт доступа. Сам получатель
  всегда получает 404, в том числе по ID записи и изображения. Фото, скопированное
  из его желания, остаётся доступным через исходное желание, но не раскрывает
  наличие сюрприза. Изменять/архивировать/удалять может только автор, пока он
  остаётся другом получателя. После удаления дружбы доступ автора тоже закрывается,
  записи сохраняются для остальных друзей. Эти пространства не дают сессий или
  членства группы; старые групповые сюрпризы не переносятся и не открываются друзьям.
- Приглашение — случайный одноразовый bearer-секрет со сроком 7 дней. Хранится
  только HMAC-хеш; новое приглашение и отзыв отменяют старое. Только вошедший
  пользователь с правильными Origin/CSRF может явно принять ссылку; просмотр,
  `/start` и предпросмотр мессенджера не создают дружбу. Передавайте ссылку лично:
  принять её может любой получатель ссылки, а не только выбранный в Telegram
  контакт. Входящего пользователя определяет проверенная подпись Telegram,
  а не параметр ссылки. Список контактов и номера телефонов не запрашиваются.

- Серверная матрица доступа к спискам, каждому объекту и изображению.
  Получатель не получает собственные сюрпризы даже по известному ID.
  Недоступный и несуществующий объект возвращают одинаковый 404.
- Идентичности отделены от внутренних ID, Telegram username не участвует в авторизации.
- Подпись Telegram initData (HMAC-SHA256), давность, обязательная проверка членства
  для группового пространства. Личные пространства изолированы по владельцу:
  вход без группы сам по себе не предоставляет доступ к каталогу, чужим записям
  или медиа; доступ к вишлисту друга требует отдельно подтверждённой дружбы.
  Сбой проверки группы может дать только личную сессию при включённом
  `TELEGRAM_ALLOW_PRIVATE_LOGIN`, но никогда не разрешает доступ к группе.
- PostgreSQL-сессии: HttpOnly cookie, Secure в HTTPS, SameSite=Lax,
  хеширование session token с секретом, ограниченный срок жизни, CSRF + Origin.
- В WebView `Sec-Fetch-Site: cross-site` не отменяет точное совпадение Origin.
  Для GET/HEAD без Origin при такой метке требуется `X-Wishlist-Request: same-origin`;
  браузерные запросы с чужого сайта не могут добавить этот заголовок без CORS
  preflight, который не разрешён. Запись всегда требует правильного Origin,
  а изменение данных в сессии — также CSRF-токена. Чужой и `null` Origin запрещены.
- Нет публичной папки фотографий. Удалённые от записей ранее прикреплённые фото
  не становятся вновь доступными загрузившему; у черновых загрузок есть TTL.
- Никаких произвольных HTML-описаний, SVG и внешних hotlinked картинок.
- SSRF: HTTP(S), без credentials/нестандартных портов; проверка **всех** результатов DNS,
  IPv4/IPv6, запрет непубличных IP и IPv6 transition-адресов; TCP-соединение к
  проверенному числовому IP (без повторного DNS), исходный Host и TLS SNI с проверкой
  сертификата. Каждый редирект и изображение проверяются заново. Proxy из окружения
  не используются. Ответы ограничены по размеру, времени и перенаправлениям.
- Ограничение частоты в общей БД; семафор автозаполнения на каждый API-процесс.

## Не защищается / требует эксплуатации

- Владелец сервера и БД видит данные. End-to-end шифрования нет.
- Друг может переслать фото, ссылку или скриншот. Уже полученные данные нельзя отозвать.
- Все процессы и пользователи локального компьютера остаются в доверенной зоне.
- Нельзя рассчитывать на приватность только по UUID. Файлы и бэкапы требуют прав ОС.
- DNS-вызов системного resolver имеет собственный системный таймаут; HTTP-срок
  ограничен, но для жёсткого общего DNS/HTTP deadline в production рекомендуется
  контролируемый DNS resolver и egress firewall. Запрет сетевого доступа к
  инфраструктуре на уровне сети дополнительно защищает от ошибок SSRF.
- CSP разрешает официальный Telegram SDK и Google Fonts. Без сети интерфейс работает
  системным шрифтом; для полностью автономного production разместите шрифты локально.
- Конкретные магазины могут блокировать скрейпинг. Обход CAPTCHA/JS-защит не реализован.
- Результаты извлечения метаданных — черновик; цена не отслеживается автоматически.
- При большой компании каталог может выполнять много проверок членства. Для первой
  версии это намеренный fail-closed подход без очередей; масштабирование требует
  пакетной фоновой синхронизации, а не снятия проверок.
- Для нескольких API-реплик нужно общее файловое/S3-хранилище, а не независимые диски.
- Лимит входа за Nginx намеренно применяется к адресу reverse proxy без доверия
  пользовательскому X-Forwarded-For. Он общий для входящих клиентов этого proxy;
  при публичном запуске добавьте отдельный доверенный edge-rate-limit.
- Постоянное удаление аккаунтов/данных и срок хранения ушедших участников необходимо
  согласовать до публичного запуска. Сейчас данные сохраняются, доступ закрывается.

Не входят в версию: бронирования, статусы покупок, платежи, комментарии, несколько
пользовательских списков, управление несколькими групповыми сообществами, регистрация без Telegram,
webhook и WebSocket. Эти функции намеренно не имитируются.
