# Проверка перед использованием

## Автоматические сценарии

Из корня:

```powershell
.\.venv\Scripts\python -m pytest backend/tests -q
.\.venv\Scripts\ruff check backend/src backend/tests --config backend/pyproject.toml
cd frontend
npm run test
npm run build
npm audit
```

Backend-тесты используют изолированную SQLite in-memory базу с включёнными внешними
ключами. Проверяются CRUD, обязательные поля, точная цена, архив, независимое копирование,
права автора, запрет собственных сюрпризов/фото, изоляция сообществ, потеря членства,
сессии/Origin/CSRF, подпись Telegram, регистрация и повторный вход, SSRF и парсинг.

Для дополнительного запуска того же набора на PostgreSQL используется **исключительно
отдельная одноразовая база `wishlist_test`**, не `wishlist`:

```powershell
docker compose exec db sh -c 'createdb -U "$POSTGRES_USER" wishlist_test'
# Тесты и зависимости надо предоставить контейнеру или окружению, имеющему доступ к db.
# TEST_DATABASE_URL=postgresql+psycopg://...@db/wishlist_test
```

Fixture удаляет/создаёт таблицы только в `wishlist_test` между тестами. Не направляйте
её на данные пользователей; проверка имени БД намеренно запрещает другие имена.

Frontend unit-тесты проверяют неинтерактивный архив и авторское меню, переключение
типов без потери данных, сохранение ручных правок при автозаполнении и возможность
сохранить подарок после ошибки метаданных. Также проверяются автоматические превью
социальных ссылок и магазинов, отсутствие импорта цены товара в номинал сертификата,
режим «От суммы» и игнорирование ответа для изменённой ссылки.

## Браузер

При запущенном Docker Compose и выполненном `seed`:

```powershell
cd frontend
npx playwright install chromium
npm run test:e2e
```

Playwright проверяет реальный Nginx → API → PostgreSQL: вход, создание, архив,
восстановление, подтверждённое удаление, профиль друга, сюрприз и мобильную вёрстку.
Скриншоты — `frontend/test-results/`, трассировки сохраняются при ошибке.
Браузерные тесты создают и удаляют записи с уникальным названием `Проверка ...`.

## Что всё равно проверяется вручную

- Настоящий Telegram Mini App на телефоне и desktop, а не имитация initData.
- Права бота в группе и реальный выход/повторный вход участника.
- Магазины, которыми пользуется ваша компания: извлечение не гарантируется для всех сайтов.
- Реальные ссылки Instagram, Pinterest и Telegram: публичное превью зависит от
  доступности публикации, авторизации, региона и антибот-защиты площадки.
- Восстановление БД и медиа из согласованного бэкапа в отдельном проекте.
- Навигация клавиатурой и системным скринридером в используемых браузерах.

Токен Telegram не входит в проект, поэтому живую Telegram-интеграцию без ваших
настроек проверить невозможно. Это не заменяется небезопасным выбором Telegram ID.

## Проверено при реализации

- После личного Telegram-входа, приглашений и сюрпризов друзей: 165 backend-тестов
  SQLite, Ruff, 138 frontend unit-тестов, TypeScript и production-сборка.
  Проверяются подтверждение/отзыв/истечение одноразовых приглашений, взаимная
  дружба без группы, отсутствие транзитивного доступа, запрет изменений чужих
  записей, общие сюрпризы прямых друзей, скрытие от получателя (включая фото/архив),
  отзыв доступа у автора после удаления дружбы и изоляция групповых сюрпризов.
  Отдельно проверяются WebView Origin/CSRF, сохранность launch-данных, ограниченные
  GET-повторы и отсутствие автоматических повторов записи. Мобильные smoke-проверки
  окна приглашения и формы сюрприза выполнены с подменёнными API-ответами;
  они не заменяют реальное подтверждение дружбы с двух Telegram-аккаунтов.
- После добавления загрузки фото по ссылке — 73 backend-теста на SQLite и PostgreSQL 17
  (прямые ссылки, SSRF, формат/размер,
  приватность фото, CSRF, общий лимит загрузок).
- 13 frontend unit-тестов, TypeScript и production-сборка.
- Docker Compose: отдельная миграция, seed и повторный seed, healthcheck API/web/БД.
- `alembic check` на PostgreSQL: расхождений схемы и моделей нет.
- `npm audit`: 0 известных уязвимостей на момент установки.
- 3 браузерных сценария Playwright: CRUD/архив/сюрприз друга, мобильный экран/редирект
  с маршрута собственных сюрпризов и импорт фото по ссылке с предпросмотром.
  Первые два проверяют реальную связку Docker/Nginx/API/PostgreSQL; сценарий
  предпросмотра использует подменённый ответ импорта, чтобы не зависеть от внешнего сайта.
- После редизайна, сертификатов и режима цены «От»: 85 backend-тестов SQLite,
  21 frontend-тест, TypeScript и production-сборка. Проверка `alembic check`
  после миграции рабочей PostgreSQL не находит расхождений моделей и схемы.
- Четвёртый браузерный сценарий проверяет отдельный раздел сертификатов,
  автоматическое название магазина (метаданные подменены), сохранение нижней цены,
  повторное редактирование и мобильную форму.
- Резервный импорт Telegram проверяется на HTML-фикстурах: имя канала, первая
  фотография нужного поста/альбома, запрет подстановки аватара и соседних сообщений,
  сбой embed/скачивания фото, SSRF, закрытые ссылки и общий лимит времени.
  Живой запрос к Telegram из текущего окружения не прошёл; доступность конкретных
  публикаций надо проверить отдельно.

Есть предупреждение upstream Starlette о будущем переходе тестового клиента с
`httpx` на `httpx2`; на выполнение текущего набора тестов оно не влияет.
