# Тепло — вишлисты для своих

Модульный монолит: личные вишлисты,
скрытые от получателя сюрпризы, визуальный архив, фотографии, автозаполнение по ссылке,
Telegram Mini App и бот. Интерфейс на русском, адаптирован для компьютера и телефона.

**Стек:** Vue 3 / TypeScript / Vite, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL 17,
aiogram 3, Nginx, Docker Compose. Redis и внешние платные сервисы не нужны.

## Быстрый локальный запуск

Нужны Docker Desktop с включёнными Linux-контейнерами и Docker Compose v2.
В PowerShell из корня проекта:

```powershell
Copy-Item .env.example .env
# Откройте .env и замените SESSION_SECRET случайной строкой длиной >= 32 символов.
# Генерация, если установлен Python:
python -c "import secrets; print(secrets.token_urlsafe(48))"

docker compose up -d --build
docker compose exec api python -m src.cli seed
```

Откройте **http://localhost:3000** и нажмите «Войти в локальную версию».
Вход осуществляется только под фиксированным тестовым пользователем. Друзья и
демонстрационные желания создаются командой `seed`; повторный вызов не создаёт
дубликатов и не перезаписывает существующие записи. Seed не запускается автоматически.

При `docker compose up` отдельный одноразовый сервис `migrate` применяет миграции
до запуска API. Сам API миграции не выполняет. Для проверки состояния:

```powershell
docker compose ps
docker compose logs api migrate
```

Бот без токена не нужен. Единственный опубликованный порт — **127.0.0.1:3000**.
API, PostgreSQL и папка фотографий не публикуются наружу. Используйте именно
`localhost`, а не IP компьютера: проверяются Host и Origin.
Обычный HTTP localhost **не является** рабочим Mini App на телефоне.

```powershell
docker compose stop       # Остановка с сохранением данных
docker compose up -d      # Повторный запуск
docker compose down      # Удалить контейнеры, НЕ данные
```

Не используйте `down -v`, если хотите сохранить базу и изображения.

## Проверка фронта без Tuna и Telegram

Для быстрой проверки интерфейса есть отдельный локальный стек. Настройки API в
нём заданы прямо в `compose.dev.yaml`, поэтому боевой `.env` не нужен; не
поднимаются nginx, бот и туннель. При открытии страницы приложение сразу входит
как тестовый пользователь из `DEV_USER_ID`. Переменную можно задать в окружении
(Compose также подставит её из `.env`), по умолчанию используется локальный
демонстрационный ID.

```powershell
docker compose -f compose.dev.yaml up -d --build
docker compose -f compose.dev.yaml exec api python -m src.cli seed
```

Откройте **http://localhost:5173**. Дополнительно нажимать «Войти в локальную
версию» не нужно — вход выполняется автоматически. `seed` достаточно выполнить
один раз; если вы поменяли `DEV_USER_ID`, выполните его снова. Например, в
PowerShell:

```powershell
$env:DEV_USER_ID = '11111111-1111-4111-8111-111111111111'
docker compose -f compose.dev.yaml up -d --force-recreate api
docker compose -f compose.dev.yaml exec api python -m src.cli seed
```

Все атомарные компоненты собраны на отдельной странице **http://localhost:5173/ui**
(в дев-сборке в шапке есть ссылка «UI-кит»). Она показывает кнопки, поля,
состояния загрузки, пустые состояния, аватары и диалоги — удобно проверять
правки примитивов без перехода по разным экранам.

Исходники `frontend/` смонтированы в контейнер. Правки `.vue`, `.ts` и `.css`
подхватываются Vite без пересборки образа. Образ `web-dev` нужно пересобирать
только после изменений `package.json` или `package-lock.json`:

```powershell
docker compose -f compose.dev.yaml up -d --build web-dev
```

Локальный стек использует отдельный проект Compose `friends-wishlist-dev` и
свои volume, поэтому не конфликтует с основным `docker compose up`. Остановка:

```powershell
docker compose -f compose.dev.yaml stop
docker compose -f compose.dev.yaml down      # удалить контейнеры, сохранить данные
docker compose -f compose.dev.yaml down -v   # полностью сбросить тестовые данные
```

### Если Tuna возвращает 404

Docker Compose запускает приложение, но **не запускает туннель Tuna**.
После перезагрузки компьютера или закрытия клиента туннель нужно поднять отдельно.
404 на публичном адресе может означать, что для домена нет активного туннеля;
это не обязательно ошибка маршрутов приложения.

1. Проверьте контейнеры: `docker compose ps`. Сервисы `db`, `api`, `web`
   должны быть `healthy`. При необходимости выполните `docker compose up -d --build --wait`.
2. Проверьте приложение напрямую, передав Host домена из `PUBLIC_BASE_URL`:

   ```powershell
   curl.exe -i -H "Host: fast-tundra-1847.a.tuna.free" http://127.0.0.1:3000/api/v1/health
   ```

   Ожидается `200` и `{"status":"ok"}`. Если вы используете другой домен,
   подставьте его в команды ниже и выше. При публичном `PUBLIC_BASE_URL`
   запрос с Host `localhost:3000` намеренно отклоняется — это защита, а не сбой.

3. Запустите Tuna в отдельном терминале и оставьте его открытым:

   ```powershell
   tuna http 127.0.0.1:3000 --domain=fast-tundra-1847.a.tuna.free --inspect=false --https-redirect
   ```

   Дождитесь сообщения `Forwarding https://... -> 127.0.0.1:3000`.
   Полный домен должен совпадать с доменом в кабинете Tuna и `PUBLIC_BASE_URL`
   в `.env`. Не подменяйте Host на localhost.

4. Проверьте публичный API:

   ```powershell
   curl.exe -i -H "tuna-skip-browser-warning: 1" https://fast-tundra-1847.a.tuna.free/api/v1/health
   ```

   Если локально `200`, а снаружи по-прежнему 404, проверьте точное имя домена,
   аккаунт Tuna и сообщения клиента о подключении. Если домен изменился, обновите
   `.env`, выполните `docker compose up -d api web` и обновите URL Mini App в Telegram.
   404 только на конкретном API-объекте может быть штатной проверкой доступа;
   не отключайте её ради исправления туннеля.

Ошибки TLS (`certificate has expired`, `CRYPT_E_REVOCATION_OFFLINE`) — отдельная
проблема, не HTTP 404. Проверьте дату и время Windows, доступность серверов
проверки сертификатов, влияние VPN/прокси и обновления клиента Tuna. Если истёк
сертификат публичного домена, проблему должен устранить провайдер туннеля.
Не используйте `curl -k` и не отключайте проверку сертификатов.
Подробности настройки: [START_DOCKER_TUNA.md](START_DOCKER_TUNA.md).

## Возможности

- Один личный вишлист независимо от сообщества.
- Списки сюрпризов изолированы по сообществу; получатель не видит ни записи,
  ни архив, ни количество, ни фотографии. Администраторского обхода доступа нет.
- Создание идеи (обязательно название), подарка и магазина для сертификата
  (обязательно HTTP(S)-ссылка). Сертификаты — отдельный раздел в каждом списке.
  При отсутствии названия показывается домен. Тип можно менять без очистки полей.
- Цены — `numeric(14, 2)` / `Decimal`, необязательные, неотрицательные, с валютой;
  пустая цена отличается от нуля. Режим «Примерно» или «От суммы» сохраняется
  при редактировании и копировании в сюрприз.
- CRUD и архив доступны только автору; для вишлиста автор обязан быть получателем.
  Доступ требует активного членства, даже для автора записи.
- Архив внизу того же списка: карточки с читаемой текстовой отметкой,
  без открытия и активных ссылок. Клавиатурное меню восстановления/удаления доступно автору.
- Сюрпризы создаются напрямую в общем списке друга. Фотографию прикрепляет только
  её загрузчик; каждый запрос проверяет доступ к связанным записям, право загрузившего не обходит ACL.
- Фото в начале формы: крупная кнопка загрузки файла, предпросмотр целиком без обрезки
  и раскрываемая загрузка по прямой HTTP(S)-ссылке на изображение.
  JPEG/PNG/WebP проверяются Pillow и перекодируются в JPEG без EXIF. При загрузке
  по ссылке используется SSRF-защита; изображение сохраняется локально, не hotlink.
- Автозаполнение по нажатию (best-effort): название, цена и фото извлекаются из
  публичных страниц и JSON-эндпоинтов, а также из JSON-LD Product/Offer, Open Graph,
  Twitter Cards, встроенного JSON состояния и заголовка. Поддерживаются, в частности,
  Ozon, Wildberries, Яндекс Маркет, Lamoda, Мегамаркет, AliExpress, Золотое яблоко,
  Авито и другие магазины. Для Авито автозаполнение запускается при вставке или уходе
  из поля ссылки. Используется обычный браузерный User-Agent без cookies, входа,
  выполнения JavaScript и обхода CAPTCHA/JS-защит; при проверке безопасности или блокировке
  показывается честное предупреждение. Короткие ссылки могут разрешаться редиректом,
  но подмена на другой товар не принимается. Неоднозначная цена остаётся пустой.
  Заполняются только пустые, не изменившиеся во время запроса название, цена и фото.
  Личное описание — пожелания и подсказки автора, оно не подставляется из магазина.
  Ошибка или недоступность данных не мешают сохранить ссылку и заполнить поля вручную.
- Ссылки Instagram, Pinterest (включая `pin.it`) и публичные сообщения Telegram
  можно сохранять как подарки. При уходе из поля ссылки автоматически запрашивается
  публичное превью; у Telegram используется публичная embed-страница.
  Если превью Telegram или его фото недоступны, дополнительно проверяется публичная
  веб-страница конкретного поста: берутся имя канала и первая фотография сообщения.
  Аватар канала и фотографии соседних постов не подставляются. Повторная попытка
  использует те же ограничения размера, проверку SSRF и общий лимит времени.
  У магазинов для сертификатов также автоматически загружаются доступные название
  и фото, но не цена товара — номинал указывает человек.
  Закрытые посты, страницы с авторизацией и антибот-защитой могут не отдать фото;
  это не мешает сохранить ссылку и добавить фото вручную. Бот и меню «Поделиться»
  для этого не нужны. Проверки SSRF и доступа к локальным фотографиям сохраняются.
- Контрастная тема «Увидел — вспомнил»: чернильный текст, синие действия,
  небольшие оранжевые акценты, белый фон реальных фотографий.
- Состояние загружается при открытии экрана и изменениях, а также при возвращении
  в приложение (не чаще одного раза за 15 секунд). При потере доступа данные очищаются.

## Структура

```text
backend/src/
  modules/{users,auth,communities,gifts,media}/
  integrations/{telegram,product_metadata}/
  infrastructure/       # БД, rate limiting
  main.py               # HTTP-приложение и защитные middleware
  cli.py                # Seed, настройка Telegram, очистка, OpenAPI
backend/migrations/     # Версионируемая схема Alembic
backend/tests/          # Бизнес-правила, API, авторизация, медиа, SSRF
frontend/src/
  pages/                # Экраны-роуты
  components/           # Все Vue-компоненты
  shared/               # HTTP-клиент, сгенерированные типы, общая логика
  styles/               # Tailwind v4: тема и слои стилей
  integrations/telegram/# Изолированный SDK-адаптер
frontend/tests/         # Vitest (unit) и Playwright (e2e)
infra/docker/           # Dockerfiles, same-origin reverse proxy
```

## Разработка без Docker для API и интерфейса

Python **3.10+** (контейнер использует 3.12), Node **22.22.2+** рекомендуется.
PostgreSQL можно оставить в Compose; не добавляйте ему публичный порт без необходимости.
Для быстрых тестов используется SQLite-адаптер, рабочая база — PostgreSQL.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install --upgrade pip
.\.venv\Scripts\python -m pip install -e './backend[test]'
cd frontend
npm ci
npm run dev
```

Для самостоятельного API задайте `DATABASE_URL`, `SESSION_SECRET`,
`PUBLIC_BASE_URL=http://localhost:3000` и локальные настройки из `.env.example`,
затем из `backend/`:

```powershell
..\.venv\Scripts\alembic upgrade head
..\.venv\Scripts\python -m src.cli seed
..\.venv\Scripts\uvicorn src.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Vite проксирует `/api` на `127.0.0.1:8000`, сохраняя исходный Host.
Снимок проверенных Python-зависимостей сохранён в `backend/requirements-dev.lock.txt`;
Docker использует его как constraints. Для воспроизводимой установки добавьте
`-c backend/requirements-dev.lock.txt` к команде `pip install`.
`.env` читается относительно текущей директории: при прямом запуске из `backend`
передайте переменные окружения или создайте там локальный `.env` (не коммитьте).

## Проверки

### Форматирование фронтенда

Prettier установлен как dev-зависимость в `frontend`. Запуск из корня проекта:

```powershell
cd frontend
npm ci
npm run format
npm run format:check
```

Первый запуск форматирует Vue, TypeScript, CSS, HTML и JSON фронтенда,
второй только проверяет форматирование.
Сгенерированная API-схема и результаты сборки/тестов исключены.

### Тесты и сборка

```powershell
.\.venv\Scripts\python -m pytest backend/tests -q
.\.venv\Scripts\ruff check backend/src backend/tests --config backend/pyproject.toml
cd frontend
npm run test
npm run build
npm audit
# При работающем локальном Compose и выполненном seed:
npx playwright install chromium
npm run test:e2e
```

Контракт API — OpenAPI; frontend-типы генерируются, не редактируются вручную.
Из `backend/`, с настроенными переменными:

```powershell
..\.venv\Scripts\python -m src.cli export-openapi | Set-Content -Encoding utf8 openapi.json
cd ../frontend
npm run generate:api
```

Файл `backend/openapi.json` и `frontend/src/shared/api-schema.d.ts` сохранены в проекте.
Схема также доступна по `/api/v1/openapi.json` через единый вход.

## Telegram и HTTPS

См. [START_DOCKER_TUNA.md](START_DOCKER_TUNA.md). Понадобятся токен BotFather,
Telegram chat ID, бот-администратор группы и публичный HTTPS-вход.
Проверка подписи `initData`, срока действия и членства выполняется только сервером.
Cookie-сессии хранятся в PostgreSQL; изменяющие запросы требуют Origin и CSRF-токен.
В production включённый development-вход приводит к отказу запуска.

## Лимиты и эксплуатация

Название: 200 символов; описание: 5000; URL: 2048; фото: 5 МиБ и 16 млн пикселей,
после обработки до 2400×2400. Нельзя вставлять HTML или SVG-фото.
Загрузки: 15/мин на пользователя; автозаполнение: 6/мин на пользователя,
3 одновременных операции на API-процесс; вход: 20/мин на адрес клиента.
Сетевой ответ HTML: 2 МиБ, до 3 редиректов, таймаут 8 секунд на HTML или фото.

Перед постоянным использованием настройте резервное копирование базы и media-volume,
проверьте восстановление и периодически выполняйте очистку:

```powershell
docker compose exec api python -m src.cli cleanup
```

Очистка удаляет просроченные сессии и неиспользуемые изображения старше 24 часов,
но не изображения с живыми ссылками.
